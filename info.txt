Offline CodeGPT - setup and feature notes
==========================================

Prerequisites
-------------
- Windows PowerShell
- Python 3.11+
- Ollama (https://ollama.com/download)

Quick setup
-----------
1. Create and activate the virtual environment:

   py -3 -m venv venv
   .\venv\Scripts\Activate.ps1

2. Install dependencies and initialize Django:

   pip install -r requirements.txt
   Copy-Item .env.example .env
   python manage.py migrate
   python manage.py check

3. Start Ollama and download local models:

   ollama serve
   ollama pull qwen2.5-coder:1.5b
   ollama pull llava:latest
   ollama pull nomic-embed-text

4. Start the app in another PowerShell window:

   .\venv\Scripts\Activate.ps1
   python manage.py runserver

The app is then available at http://127.0.0.1:8000/.

Portable setup script
---------------------
The setup script automates the virtual environment, dependencies, migrations,
health checks, and Ollama model checks:

   Set-ExecutionPolicy -Scope Process Bypass
   .\scripts\setup-offline.ps1

Optional examples:

   .\scripts\setup-offline.ps1 -Model qwen2.5-coder:7b
   .\scripts\setup-offline.ps1 -SkipOllama
   .\scripts\setup-offline.ps1 -SkipVision

If Ollama is installed elsewhere or should be configured manually, use
-SkipOllama and run the ollama commands above yourself.

Project folder watcher
----------------------
Keep a project index up to date in the background:

   python manage.py watch_project C:\path\to\project --username YOUR_USER

Useful options:

   python manage.py watch_project C:\path\to\project --username YOUR_USER --once
   python manage.py watch_project C:\path\to\project --username YOUR_USER --interval 2

The watcher incrementally indexes supported files and updates semantic
embeddings when the local files change.

Feature notes
-------------
- Semantic RAG uses the Ollama embedding endpoint and the model in
  OLLAMA_EMBED_MODEL (default: nomic-embed-text). If embeddings are unavailable,
  the app falls back to lexical search.
- Document chat supports TXT, Markdown, code, PDF, and DOCX files with local
  source citations. PDF/DOCX support uses pypdf and python-docx.
- OCR is available from the workspace OCR control for images and scanned PDFs.
  It uses the local vision model and PyMuPDF for PDF page rendering.
- Offline voice input uses the local faster-whisper runtime. Use the
  "Record offline audio" control in the workspace.
- Live tool/job events are streamed through /api/agent/events/ and displayed in
  Workspace > Metrics. Polling remains available as a fallback.
- Smart model routing chooses a local model when no model is manually selected.
  Hardware hints can be set with LOCAL_AI_MEMORY_GB and LOCAL_AI_GPU.
- Secret redaction removes vault values and common token/password patterns before
  indexing or sending content to a local model. Original project files are not
  modified.
- Encrypted backups are available from the UI or
  /api/backup/?encrypted=1. The encryption key is derived from DJANGO_SECRET_KEY;
  keep that setting stable or older encrypted backups cannot be restored.
- The model benchmark is available in Ollama settings. Enter comma-separated
  local model names; the recommendation optimizes measured speed, not quality.

Useful environment variables
----------------------------
Set these in .env when needed:

   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=qwen2.5-coder:1.5b
   OLLAMA_VISION_MODEL=llava:latest
   OLLAMA_EMBED_MODEL=nomic-embed-text
   WHISPER_MODEL=base
   WHISPER_DEVICE=cpu
   WHISPER_COMPUTE_TYPE=int8
   LOCAL_AI_MEMORY_GB=16
   LOCAL_AI_GPU=auto

The exact model names depend on the models installed with `ollama list`.

Troubleshooting
---------------
- Ollama connection errors: start `ollama serve`, verify `ollama list`, and
  check OLLAMA_BASE_URL.
- Semantic search falls back to keyword search: run
  `ollama pull nomic-embed-text` or set OLLAMA_EMBED_MODEL to an installed
  embedding model.
- OCR errors: confirm PyMuPDF is installed with
  `pip install -r requirements.txt` and that the configured vision model exists.
- Whisper errors: install the requirements, ensure the Whisper model can be
  downloaded once, and use WHISPER_DEVICE=cpu with WHISPER_COMPUTE_TYPE=int8
  on CPU-only machines.
- PowerShell blocks scripts: run
  `Set-ExecutionPolicy -Scope Process Bypass` for the current window only.
- To verify the project after changes, run:

   python manage.py check
   node --check static\chat\app.js
   git diff --check

Coding workspace feature set
----------------------------
- Local LSP support is available at `/api/coding/lsp/`. POST a filename,
  content, and optional operation (`diagnostics`, `definition`, `references`,
  `completion`, or `all`). It returns an LSP-shaped response with diagnostics,
  symbols, definitions, references, and completion candidates without sending
  source code outside the device. The current built-in backend uses Python AST
  parsing and safe regex parsing for common languages; external language-server
  processes can be added later behind the same contract.
- AST-safe refactoring previews are available at `/api/coding/refactor/`.
  Submit one buffer or a JSON `files` array with `old_name` and `new_name` to
  preview coordinated renames. The response includes unified diffs, affected
  files, replacement counts, approval requirements, and rollback support; it
  never writes files automatically.
- Issue-to-PR planning is available at `/api/coding/issue-to-pr/`. Submit an
  issue title, description, optional file list, and test command to create an
  approval-gated AgentTask workflow. The workflow uses the existing isolated
  agent-worktree controls and does not edit or merge code automatically.
- Diff-aware PR review is available at `/api/coding/pr-review/`. Send a JSON
  `files` array, unified `diff`, and test evidence to receive local quality and
  security findings, line-aware comments, merge readiness, and a review
  fingerprint. A new push should trigger re-review; this endpoint never
  merges or publishes code.
- Local CI planning is available at `/api/coding/local-ci/`. Send the project
  file manifest to detect Python, Node, or Rust lint/test/build commands. The
  returned pipeline is approval-gated, network-blocked, locally cached, and
  designed to produce JSON, JUnit, coverage, and SARIF artifacts. Use the
  existing guarded test runner to execute selected commands.
- Coding security and SBOM reporting is available at
  `/api/coding/security-sbom/`. It combines the local source/dependency scan
  with SPDX output, SARIF output, license inventory, and optional matches from
  a user-imported advisory snapshot. No live vulnerability lookup is made;
  advisory freshness depends on the imported local database.
- Browser debugging is available at `/api/coding/browser-debug/`. It creates a
  local Playwright test, analyzes a supplied report, and returns a safe repair
  loop for console/network/screenshot/trace evidence. Browser targets remain
  local-only and generated patches require explicit approval.

Privacy reminder
----------------
Keep .env and local model/data directories out of Git. Do not store API keys or
passwords in prompts or project files. The Privacy dashboard shows local mode,
network locking, data location, and redaction controls.

Latest workspace features
-------------------------
- Hybrid RAG combines lexical matching, semantic embeddings, phrase matching,
  filename boosts, and reranking. Optional weights are
  RAG_LEXICAL_WEIGHT, RAG_SEMANTIC_WEIGHT, and RAG_RERANK_WEIGHT.
- The Memory panel automatically keeps recent conversation turns within the
  model context budget and stores a local summary of older turns.
- Git workspace controls include local branch create/switch, blame, staged
  commits, and guarded file rollback. Rollback requires typing ROLLBACK.
- AI patch review uses optimistic concurrency. If an indexed file changed after
  preview, the patch is rejected until the file is reloaded. Accepted patches
  refresh the local index and can be rolled back.
- Agent plans accept custom one-line checkpoints. Write, execute, and Git steps
  are approval-gated; plans can be paused, resumed, retried, or reset.
- Local plugins use approved manifests and permissions. Supported local tools are
  project.search, project.read, and agent.plan. Plugin execution never calls a
  remote provider.
- Permission profiles are available in the secure runtime policy: Read only,
  Developer, and Unrestricted. Read-only mode blocks code execution, Git writes,
  rollback, and project test execution.
- Test workspace can discover Django, Pytest, NPM, Cargo, and Go test runners.
  Select a detected command and explicitly approve it before running; execution
  is capped at 60 seconds.
- Evaluation Lab compares model score, latency, throughput, completion rate,
  and score coverage. Scores are local evaluation signals, not a guarantee of
  answer quality.
- Interrupted agent jobs can be recovered from the Agent workspace or with:

   python manage.py recover_jobs
   python manage.py recover_jobs --username YOUR_USER

Recovery returns jobs left in `running` to a queued checkpoint so they can be
reviewed and run again safely.

Next workspace feature set
--------------------------
- Multi-runtime adapters share chat, embeddings, vision, and streaming tool
  payloads across Ollama, LM Studio, and llama.cpp. Select the runtime in
  Settings. OpenAI-compatible runtimes should expose /v1/models,
  /v1/embeddings, and /v1/chat/completions locally.
- Agent worktrees are created from the Agent workspace under
  .agent-worktrees. Review or compare a task before using the explicit Merge
  or Discard action. Git must be installed and the project must be a Git repo.
- Knowledge Collections provide named project RAG sets. Choose Hybrid RAG or
  Full document mode, then add project files to the collection before chatting.
- Code indexing extracts Python AST symbols and regex symbols for other common
  languages. Inspect them with /api/project/symbols/ and impact hints with
  /api/project/symbol-impact/.
- Model lifecycle controls support local model warm-up, Ollama unload, GGUF
  import into local_models, and inventory refresh. GGUF import stores the file;
  configure the runtime's own model path to load it.
- MCP Connector Hub supports local JSON import/export, health checks, and
  localhost-only endpoint enforcement. Remote connector endpoints are rejected
  while offline mode is active.
- Scoped persistent memory is managed from the Memory panel or
  /api/memory/scoped/. Supported scopes are global, project, conversation, and
  workspace. Matching enabled memories are included in local prompts and can
  be edited or deleted.
- Privacy Proof records local runtime endpoint, status, purpose, and prompt
  size without storing prompt contents. View /api/privacy/ledger/ or download
  the hashed JSON report from /api/privacy/report/.
- Offline scheduler jobs are created in the Scheduler panel. Run due jobs once
  with `python manage.py run_scheduler`, or keep a local worker alive with
  `python manage.py run_scheduler --loop`. Jobs support health checks, file
  re-indexing, model warm-up, project tests, and backup reminders.
- Native onboarding diagnostics probe all three local runtime URLs and report
  Python, platform, virtual environment, model, and dependency readiness.
  Run the Windows launcher with:

   Set-ExecutionPolicy -Scope Process Bypass
   .\scripts\launch-offline.ps1

  The launcher creates .venv when needed, applies migrations, and starts the
  server on http://127.0.0.1:8000/. Install dependencies separately with
  `pip install -r requirements.txt` when setting up a new machine.

Runtime URL overrides
---------------------
The configured runtime uses the URL saved in Local runtime settings. For
diagnostics of the other local servers, optional environment overrides are:

   LOCAL_AI_OLLAMA_URL=http://127.0.0.1:11434
   LOCAL_AI_LMSTUDIO_URL=http://127.0.0.1:1234
   LOCAL_AI_LLAMA_CPP_URL=http://127.0.0.1:8080

Feature verification
--------------------
Run the following after migrations or feature updates:

   python manage.py migrate
   python manage.py check
   python -m py_compile chat\views.py chat\models.py
   node --check static\chat\app.js
   python manage.py test chat
   git diff --check

The privacy proof and local runtime adapters are designed for localhost
endpoints. Pull/delete remains Ollama-specific; LM Studio and llama.cpp model
installation is managed by their local runtime. Desktop onboarding currently
provides diagnostics and a PowerShell launcher rather than a compiled MSI.

Latest 10-feature extension set
--------------------------------
- Layout-aware document intelligence stores page, heading, paragraph, and
  table sections. Inspect a document with `/api/project/<id>/layout/`.
- Model capabilities are stored per runtime/model through
  `/api/models/capabilities/`. Probe a model with POST `model=...`; the result
  includes inferred vision, embedding, tool, JSON-schema, reasoning, context,
  quantization, and hardware hints.
- Durable MCP tasks support asynchronous task handles from `tools/call` and
  the JSON-RPC methods `tasks/get`, `tasks/update`, and `tasks/cancel`. Direct
  management is available at `/api/mcp/tasks/`.
- The zero-trust MCP gateway adds per-tool policy, risk scores, path allowlists,
  localhost-only network rules, rate limits, and signed policy hashes. Review a
  call with `/api/mcp/security/check/` before executing it.
- Code intelligence now stores symbol relations and exposes a graph from
  `/api/project/graph/?name=SYMBOL`, including references, imports, tests, and
  affected files.
- The VS Code extension adds Explain Selection, Generate Tests, and Ask
  Project commands. JetBrains plugins can use the same localhost-only
  `/api/cli/ask/` streaming contract documented in `vscode-extension/README.md`.
- Structured data analysis supports CSV, JSON, basic XLSX, and SQLite files at
  `/api/data/analyze/`. It returns schema, null counts, type hints, samples,
  filtered rows, and chart suggestions without uploading data externally.
- Evaluation replay runs a saved regression suite against a selected local
  model and records score, latency, success rate, output size, and regression
  status at `/api/evaluations/replays/`.
- Encrypted LAN sync supports peer pairing, token rotation, content-hash
  manifests, and encrypted backup bundles. Use `/api/sync/peers/`,
  `/api/sync/manifest/`, and `/api/sync/bundle/`.
- Screen understanding is available at `/api/screen/understand/` and the
  workspace now includes screenshot analysis. Local text-to-speech uses the
  optional `pyttsx3` package through `/api/speech/synthesize/`; install it with
  `pip install -r requirements.txt` on machines that need TTS.
